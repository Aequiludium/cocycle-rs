# Serial F2 transfer and high-dimensional decision

[Reports](README.md) / [H2 foundation](h2-foundation.md) / [Lifetime evidence](h2-workspace.md)

## Decision and scope

T4-T9 produce no production-admitted optimization. M2 is a justified no-go for
an optimized cross-dimension workspace; T10 retains existing specialized H0/H1
and dimension-generic prime-field H2+ dispatch; T11 starts no parallel follow-up.
Research closure does not deliver an optimized generic kernel, arbitrary-dimension
proof, parallel persistence, merge or release. In particular, the substantial
T3 H2 gains are real within that comparison, but its failed H1 admission control
still prevents enabling that private prototype by default.

This report publishes a bounded summary of previously frozen local experiments
and fresh correctness validation. It changes no production reducer, owner layout,
workspace retention policy, API, dependency or MSRV. T4-T8 generators, switches,
workers and experiment commits are not included in the submission history.
The associated tasks are [M2 #48](https://github.com/Aequiludium/cocycle-rs/issues/48),
[T10 #44](https://github.com/Aequiludium/cocycle-rs/issues/44) and
[T11 #45](https://github.com/Aequiludium/cocycle-rs/issues/45).

## Seven transfer questions

| Question | Answer and evidence limit |
| --- | --- |
| Which H1 mechanisms transfer to H2? | Complete owned clearing and certified apparent/initial-emergent/virtual reconstruction preserve the tested algebra; none of the later shortcut candidates earns default admission. H1 cycle filtering remains specialized. |
| Which arguments are dimension independent? | Adjacent-dimensional coboundary linearity, a shared total order, triangular transforms and mutual apparent certificates do not depend on q=2. Actual arbitrary-dimensional implementation is not inferred from finite H3 tests. |
| What does virtual storage trade? | Omitted unit columns avoid stored transform payload but require reconstruction/enumeration and complete implicit owner lookup. Repeated duplicate32 regressions prevent treating storage savings as an unconditional time gain. |
| What does representation change? | Combinadic and two-edge owner keys change encode/lookup/storage cost. Working rows retain exact tuple order. Primitive key benefits do not establish end-to-end benefits or a valid dimension reset. |

| Can Ripser/Dory ideas combine? | Shared ordered reduction, compressed reconstruction and parity merging are compatible under explicit contracts. Our Dory-inspired rescan is not its optimized adjacency cursor; tied-case Dory failures prevent using it as a general oracle. No novelty/direct-port claim is made. |
| Does adaptive materialization help? | The fixed threshold-four source-count proxy has some favorable rows, but fails independent holdout controls. No threshold is selected from holdout and no additional pruning is admitted. |

## Algebra and source-study limits

Within a dimension, simplices use increasing filtration value then decreasing
colex. Columns are processed in reverse order and pivots in forward order. If
tau is sigma's first cofacet and sigma is tau's last facet, other columns that
contain tau have not been processed yet. The ordinary pivot is therefore tau;
the unit transform preserves R=C V. Equal value suppresses a zero bar without
erasing its pairing. Equal value alone is not a mutual certificate.

Initial emergent discovery accepts only the actual first row of an unreduced
initial column with equal value and no owner. This is exactly the pivot ordinary
reduction would accept before additions; it is not permission to reassign a pivot.
An omitted apparent owner reconstructs its unit column with a strictly later
forward owner, preserving triangularity and pivot progress. Every omitted pairing
must enter the owned next-clearing set, including zero-length pairs.

For streams, each finite cofacet enumeration has unique rows, and strict forward
advancement eventually exhausts it. Keeping each stream's minimum remaining row
as its heap head exposes the global minimum. Grouping equal heads, advancing every
contributing stream and retaining only odd multiplicity computes exactly
delta(sum sigma_i) over F2. Reinsert a popped pivot before adding its owner.
Sorted-vector streams keep their unconsumed payload; implicit rescanning trades
that storage for repeat enumeration. Adjacency order is not filtration order.

Owner presence alone is not a pruning certificate: for owned A={0,1} and active
B={0,2}, B+A={1,2}; deleting row 0 without adding A instead gives {2}. Clearing
removes reduction columns, not the simplices needed to enumerate the next level.
The terminal-only T6 filter has no later topology consumer and is the bounded
exception. The complete generic topology remains in all q3 controls.

The source study uses Ripser 01add51ff64aaf40889483260cc5c3b7d0f2a1e7 and
Dory b6d9b081f626adc60b224bb044c04e7abf5cc599. Ripser's separate topology and
columns-to-reduce lists do not justify deleting cleared topology. Dory has
specialized H1/H2 keys, adjacency cursors and input assumptions, not a generic
all-dimensional proof. These are established algorithmic ideas; no external
code was copied, and conceptual streaming ownership is not asserted as novel.

## M2 compatibility and reset contract

This audit is at the actual retained representation, not a proposed workspace
name. [M1](h2-workspace.md) resolves the first three memory questions: minimal
post-H1 reducer state is owned intervals plus complete owned death-triangle keys;
shared input/access/Execution is separate; necessary old/new topology construction
overlaps; H1 reduction state already releases before H2. Early generic release
and same-type scratch benefits remain finite, contradictory observations.

| Actual storage | Compatibility | Last use, nested ownership and safe boundary |
| --- | --- | --- |
| H1 BinaryHeap<Reverse<SimplexEntry>> | Different element type from private H2 BinaryHeap<Reverse<TupleEntry<4>>> | Decode all death edge-position keys inside the H1 reducer, then drop; no Vec<T>-to-Vec<U> reinterpretation |
| H1 TransformColumn and its additions | Different layout from private H2 Vec<Vec<usize>> | Nested additions and edge positions belong to the H1 level; no logical state or source index may cross the boundary |
| Generic working Column<Simplex> | Same Rust type across q; wraps BTreeMap with owned Simplex vertex Vecs | Release every row/node and nested vertex payload before another column/dimension; BTreeMap emptiness is not evidence of retained reusable node capacity |
| Generic Vec<Column<usize>> | Outer element type matches across q; nested BTreeMaps own level-position coefficients | After output/clear-next extraction discard all nested transformations; only then could empty outer capacity be reused, with new positions and order context |
| Generic HashMap<Vec<usize>, usize> owners | Key/value types match, meanings do not | into_keys() moves owned death keys into clear-next and consumes the map; old owner indices and coefficients cannot remain valid for q+1 |
| Generic HashSet<Vec<usize>> cleared | Existing same-type bucket reuse, not a new optimized policy | clear() removes old owned keys but retains buckets; replace the complete set with new owned keys before reduction |
| Generic Vec<Simplex> topology | Same element type, different dimension | Keep old topology alive through next_dimension; old/new level payloads necessarily overlap, then drop old level. Cleared simplices remain enumeration sources |
| Intervals, shared input, field/order context, Execution | Required live state, not reusable scratch | Own exported intervals/handoff, preserve original IDs and one budget; update dimension-specific interpretation before any new reduction |

For an admitted compatible representation, reset would require: complete owned
output/clear-next extraction, releasing obsolete nested payload, removing owners,
pivots/source positions/virtual state, installing the new dimension and ordering,
then retaining only explicitly bounded empty capacity. Type equality alone proves
none of the resource benefits. The current generic owner/transform layouts have
possible compatible outer storage; this is not a claim of incompatibility of
every generic buffer.

T9 admits no optimized representation, so M2's explicit no-go branch applies.
No cross-dimension drop/reallocate-versus-reuse ablation is manufactured, and no
M2 allocation/runtime improvement is claimed. Existing generic fallback and M1
measurements are retained. A high-water retention/release policy remains
unmeasured for an optimized generic candidate and is therefore not adopted.
M1's within-H2 tied32 scratch retains 659456 vector-capacity bytes and increases
diagnostic peak RSS 5280 to 5456 KiB in its first run, illustrating the cost.

The semantic streaming bound concerns reduction state after extraction: old
reducers need not survive with the next reducer. It is not max-of-dimension RSS:
shared inputs, results, handoff conversion, required old/new topology, allocator
retention and fragmentation remain. Vec capacity, owned payload, BTreeMap nodes,
allocator live bytes, allocation calls and process RSS are distinct quantities.
Direct allocator live-byte/allocation/reallocation/free totals are unavailable;
capacity-growth events are not allocator calls. Errors return no partial diagram;
owned locals release on cancellation/work-limit/error unwind. Existing boundary
tests inject recoverable allocation errors and retry cleanly; real universal OOM
recovery is not established. No new retained state or failure path is introduced.

## Frozen comparative protocol

The following tables summarize the original successful measurements, not fresh
benchmarks of this report commit. Every T4-T8 run has 25 H2 cases, 20 H1 controls
and four H3 controls; T9 has 20 H1 scenarios. Each stage has two independent
repeats, one discarded warmup and 15 fresh serial measured rounds per cell.
Balanced order, CPU0, Rust 1.91 release, Linux-local executables, exact F2
diagram-only pipeline-v2 workflow boundaries and one common float32 quantization
are fixed. Frequency and competing host load are uncontrolled on the Core Ultra
7 155H WSL2 environment. Native GUDHI/Ripser establish correctness, not a ranking.

Preregistered screens: H1 median ratio <=1.05 and paired upper95 <=1.10;
H2/H3 median ratio <=1.10, with repeated clear benefit in at least two families,
explained regressions and justified memory/work/complexity required for admission.
No sample/outlier is removed and no screen is weakened. T8 tuning is n16 uniform,
circle, clusters and high-fill; every n32 and remaining n16 family is holdout.
The fixed predictor is source-coboundary count, a transform-length proxy, not a
holdout-selected threshold. Baselines differ by stage and ratios cannot multiply:
T4 disables shortcuts; T5-T8 use stored apparent; T9 uses ordinary specialized H1.

Measured source identities and controller/fixture/binary fingerprints were frozen
before analysis. Generated sources, complete samples and negative attempts remain
local ignored artifacts; no durable public artifact store is configured. This
public summary does not make the original experiments publicly reproducible or
relocate their measurements onto the submitted library. The original aggregate
has 43328 completed workflow processes, 1648 separate diagnostics and 192 key
primitive processes, including recorded warmups. Build-failed attempts are
retained before sampling (T5 CRLF paths and initial T7 replacement scope); they
are not successful samples or performance evidence. Successful runs contain no
omitted mismatch or timeout. Key primitive encode/build/lookup/compare/decode
results do not explain an engine cost unless that primitive runs on its hot path.
